# Demo Script

Target length: 5-7 minutes.

## Opening

NanoClaw is a small personal agent runtime. The point is not to show a huge
automation platform. The point is to show how personal agents can stay
inspectable when they touch messages, files, memory, and scheduled work.

## Flow

1. Open the README and show the project status section.
2. Open `docs/SAFETY_MODEL.md` and explain the host/container boundary.
3. Open `docs/FUTURES_RECONSTRUCTION.md` and show the probability table.
4. Open the latest release and explain what changed.
5. Open the public discussion and ask for one narrow piece of feedback.
6. Mention `nanoclaw.website` as the future visual surface once DNS is active.

## Closing Question

What should a personal agent be allowed to execute, and what should remain a
reviewable suggestion even when the user owns the fork?

## Do Not Show

- real API keys or tokens;
- private channels or personal conversations;
- private collection files;
- contracts, invoices, or acquisition records;
- production credentials or local `.env` files.
