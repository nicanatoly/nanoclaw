# Safety Model

NanoClaw's safety model is based on keeping the system small enough to inspect
and running agents inside isolated container workspaces.

This document is a short review surface. For implementation details, see
[SECURITY.md](SECURITY.md) and [SPEC.md](SPEC.md).

## Core Boundary

Agents should not run directly on the host. They run in containers with only the
directories and credentials required for the configured workflow.

The host is responsible for:

- channel adapters;
- message polling;
- SQLite state;
- credential proxying;
- container runtime orchestration.

The container is responsible for:

- agent execution;
- workspace-scoped file access;
- task-specific tool use.

## What The Agent Can See

An agent should only see:

- the mounted group workspace;
- the per-group memory file;
- explicitly passed authentication material needed for the configured model;
- task context routed through NanoClaw.

An agent should not see:

- the full host filesystem;
- unrelated group workspaces;
- the user's entire password manager;
- host shell access outside the container;
- arbitrary environment variables.

## Credentials

Credential examples in docs and tests must be clearly fake placeholders.

Runtime credentials should be scoped and injected intentionally. Authentication
material should not be committed, logged, or copied into user-facing output.

## Human Review Points

NanoClaw is designed for personal customization, so the strongest review point
is the user's own fork. Users should review:

- skills before applying them;
- mounted directories before running agents;
- channel credentials before enabling channels;
- scheduled tasks before letting them run repeatedly;
- any custom code generated by an agent.

## Good Safety Questions

Before adding a capability, ask:

- What host resources does this expose?
- Can this be scoped to one group or workspace?
- Does this need a read-only first version?
- What would a mistaken agent action affect?
- Can a user inspect and undo the change?

## Current Known Limits

- Container isolation reduces risk but does not remove the need to review
  custom skills and mounted directories.
- Messaging channels can still expose sensitive conversation content.
- Scheduled tasks should be treated as recurring delegated actions.
- Third-party model endpoints and proxies need their own trust review.
