# Integration Map

NanoClaw should grow through narrow, useful relationships with adjacent
open-source projects rather than broad promotional outreach.

## Relationship Types

- `watch`: read and learn from the project.
- `question`: ask one narrow public question.
- `docs`: add a comparison, safety note, or setup note.
- `skill`: build an optional NanoClaw skill around the idea.
- `adapter`: explore a small integration path.
- `sponsor`: consider support after value and fit are clear.

## First Questions To Ask

- Which actions should remain suggestion-only?
- Where is the boundary between read-only automation and execution?
- What memory should remain human-readable?
- What makes a small sponsorship useful to maintainers?
- How should public agent actions be logged or reviewed?

## Public Conversation Rhythm

NanoClaw should not spray comments across unrelated repositories. A good rhythm
is:

1. star or watch a project only when it is genuinely relevant;
2. read existing issues and docs;
3. ask one narrow question if the answer is not already documented;
4. bring the answer back into NanoClaw as a doc note, test idea, or optional
   skill;
5. sponsor only after there is clear value and fit.

## Contribution Rule

Read first. Ask one narrow question. Turn useful answers into docs, tests, or
skills. Avoid drive-by promotion.
