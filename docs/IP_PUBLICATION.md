# Open-Source Publication Notes

This is not legal advice. It is project hygiene for publishing ideas, code,
AI-assisted work, docs, and exhibition material around NanoClaw.

## Code

NanoClaw currently uses the MIT License. That is simple and permissive.

For future modules where patent clarity matters, consider whether a separate
Apache-2.0 licensed repository or explicit patent policy is a better fit before
publishing.

## Ideas And Inventions

GitHub is useful for timestamped publication and collaboration. It is not a
patent office. Publishing an idea can also become prior art, which may affect
patent options.

Before publishing a potentially valuable invention:

1. Write a short disclosure note.
2. Search for similar projects.
3. Decide whether the goal is open source, defensive publication, or patent
   review first.
4. Publish only when the decision is intentional.

## AI-Assisted Work

When AI helps produce code, docs, images, or concepts:

- record the human direction and editing when it matters;
- do not list AI as an inventor;
- keep human contributors clear;
- review licenses and third-party material before publishing.

## Collection And Exhibition Material

Collection images, certificates, and NFT editions should be handled separately
from code. Rights should be documented per object before public release.

NFT ownership should not imply copyright transfer unless explicitly stated.

## Good Public Artifacts

- release notes;
- design notes;
- architecture diagrams;
- safety model docs;
- issue discussions;
- defensive publication notes;
- exhibition catalog pages.
